# הילסון — משימות תיקון ל-Wireframes

מבוסס על שתי פגישות סקירת ה-wireframes (צד נותן שירות + צד מטופל). ריכוז מ-04.08.2026.
המשימות הן שינויי UI/wireframe קונקרטיים בלבד; דיונים קונספטואליים רוכזו בנפרד למאגר הידע.

---

## חלק א' — צד נותן שירות (Provider)

### דף נחיתה וכניסה
- להסיר את מסך דף הנחיתה מתוך האפליקציה — כפתורי "הצטרף כנותן שירות" / "כמטופל" יושבים ב**דף הנחיתה הקיים** של הילסון ומפנים למערכת.
- להשאיר כניסת "הצטרפות כנותן שירות" קבועה בראש המערכת.

### הרשמה ואימות (הרשמה → אימות → הקמה)
- להציג stepper ממוספר עם שמות השלבים: **הרשמה/התחברות → אימות → הקמה**.
- להוסיף בורר **רופא מנתח / לא מנתח** (משפיע על המשך התהליך).
- **תחום התמחות**: dropdown שנפתח, אפשרות לבחור **כמה** תחומים, כולל אופציית **"אחר"**.
- להוסיף **התראה לאדמין** בכל פעם שספק מוסיף תחום "אחר".
- להזרים את רשימת התחומים מה**אקסל** הקיים ל-DB (כרגע דמו בלבד).
- **אימות טלפון** — להוסיף שלב.
- **מספר עוסק**: **חובה** — מורשה או פטור, אחד מהשניים (נדרש להפקת חשבוniות).
- **רישיון רפואי**: **חובה** — מספר **+ קובץ תעודה**.
- **רישיון מומחה**: **לא חובה** — אך אם הוזן, נדרשים **גם מספר וגם קובץ**.
- **תעודת זהות**: להוסיף **צילום ת"ז + תאריך לידה** (מזהים ראשיים נשארים מייל+טלפון).
- **להעביר להקמה (מתוך אימות)**: היכן מוכר פריטים והיכן עובד (מרפאות חוץ / בתי חולים / מיקומים). רישיונות נשארים באימות.
- **שער הסכמות (קונסנט) לפני השמירה הראשונה** — למקם במסך "מקצוע ורישוי" (המסך הראשון שבו הספק מעלה/שומר מידע). נפרד מהסכם הילסון.

### הקמה — מבנה שלבים
- סדר שלבים סופי: **סניפים → פריטים → זמינות → פרופיל → הסכם**.
- להפוך את פס ההתקדמות ל**stepper ממוספר (1–5) לחיץ** עם שמות, שמאפשר קפיצה בין שלבים.
- למקם את תווית **"העלה תמונת פרופיל"** בתוך עיגול השלב.
- **להסיר "הסדרי ביטוח" כשלב עצמאי** — עובר לתוך תמחור הפריטים.
- **תמונת פרופיל**: להעביר לפרטים האישיים בהרשמה, או להשאיר אפשרות "הוסף מאוחר יותר".

### הקמה — סניפים ומערכים
- **לשנות "מרפאה/מרפאות" → "סניף"**; כפתור **"הוסף סניף"**.
- להוסיף שדה **"סוג הסניף"** (לא "סוג מיקום"): מרפאה / בית / מכון / חדר ניתוח / אונליין.
- כל סניף מפנה ל**יחידה רפואית** שאליה הוא שייך.
- להוסיף **"הוסף חדר ניתוח"** — מוצג **רק למנתחים**; picklist של חדרי הניתוח בארץ + כתובות.
- לכל חדר ניתוח שנבחר — לשאול **סוג ההסדר הביטוחי** שהמנתח עובד תחתיו שם.
- תחת סניף — להוסיף את כל ה**מערכים** ולהגדיר קיבולת לכל מערך (ייעוצים = לפי רופאים בו-זמנית; מכון/דימות = לפי סוג בדיקה/חדרים).

### הקמה — פריטים ותמחור
- בורר **סוג פריט** מעל שדה החיפוש, מתפקד כ**פילטר**.
- סוגי פריט מותרים לפי סוג ספק: ספק יחיד (רופא) — **ייעוץ, טיפול, ניתוח, פעולה** (להסיר **מוצר**); **בדיקה** — רק למכון; רופא רגיל במרפאה — רק **ייעוץ / ייעוץ חוזר / טיפול**.
- **ייעוץ חוזר** — כתת-סוג/תיאור **בתוך** ייעוץ (הרופא לא ייצור שתי שורות בעצמו). פריט = ייעוץ + **שדה תיאור/משנה**.
- לכל פריט להציג **משך + מחיר** (משך ליד שדות המחיר); להוסיף שדה **מחיר ייעוץ חוזר** נפרד.
- **מחיר פריט מלא** — להשאיר. **להסיר "סל קופה" בייעוץ**. **סל/ס"ל — רק לניתוח**; להסתיר מספק יחיד.
- **מילוי אוטומטי של תמחור**: לפי הקופות/הסדרים שהספק בחר, למלא שורות מחיר לכל תוכנית (מכבי כסף/זהב וכו') מתוך ה**קטלוג**. הספק עורך רק מחיר פריט מלא ומחיר ייעוץ חוזר.
- להוסיף שדה **החזר / השתתפות עצמית** לכל תוכנית.
- **לשנות "קטלוג" → "הגדרת סוגי השירותים"**.
- **לא לאפשר** לספק לראות/לחפש פריטים ומחירים של ספקים אחרים — ברירת מחדל **יצירת פריט חדש**.
- לספק **מאגר מילים** לבניית שם הפריט (ייעוץ vs ייעוץ חוזר); **קוד נוצר ע"י הילסון**.
- **טיפול**: הוספת הערה/תיאור, השם נקבע ע"י הספק (למשל "זריקות בוטוקס") — ללא חיפוש.
- **ניתוח / פעולה / בדיקה**: שמות ממחירון מב"ר / קודי משרד הבריאות בלבד — לא לאפשר הקלדה חופשית.
- אחרי שמירת פריט — **שיוך הפריט** לסניפים שבהם ניתן: ייעוץ/ייעוץ חוזר/טיפול → מרפאות/סניפים; **ניתוח → חדרי ניתוח** בלבד.
- להוסיף לכל פריט: **סוגי מקרים / checkboxes** (למשל נוירולוג → כאבי ראש, קשב וריכוז) לצורך חיפוש מטופלים; **הגבלת גיל/טווח**; אפשרות **מסמכים/שאלון נדרשים** לפני הזמנה (כולל העלאת תבנית); סימון **"דורש הפנייה"**; **חוות דעת/ביקורות** על הפריט.

### הקמה — תנאים והסכם
- להוסיף **עמוד תנאי שירות** בתחילת תהליך ההצטרפות, עם קישור להסכם הגנרי.
- **לא** להציג חישוב עמלה/מחיר-נטו לכל פריט בזמן ההזנה.
- **הסכם מול הילסון בסוף ההקמה**, אחרי הזנת כל הפריטים; חתימה ב-**DocuSign** (גנרי, זהה לכולם).

### כרטיס סיכום ובקשה
- לרנדר **כרטיס סיכום בקשה**: שם (ד"ר …), טלפון, סימון מנתח, תחום התמחות.
- מקטעים: **פרטים אישיים / מקצוע / עריכה**; להוסיף **ת"ז** ולהציג **מספר עוסק** בתחתית.
- להוסיף שדה **תואר** (רופא / פרופסור) הקשור למקצוע; אם מומחה — להציג מספר מומחה + תואר במקטע המומחה.
- **מייל אישור** לספק + מסך **מעקב סטטוס**.

### התראות וסטטוסים
- הודעת **"הבקשה התקבלה / ממתין לאישור"** לספק אחרי אימות, עם הסבר שממתין לבדיקת מסמכים.
- התראת אדמין **"רופא חדש רוצה להצטרף"**.
- ב**הגדרות** — בחירה אם לקבל **מייל/התראה על כל תור חדש**.
- לתור **דורש הפנייה** — כרטיס עם מטופל/תאריך/מחיר/הפנייה + **אשר/דחה**.

### דשבורד ספק — תורים, תשלומים, בקשות
- **תורים** לפי סטטוס: מאושר / שולם במלואו / בוצע.
- **דף ראשי**: מדדי סיכום (פגישות שנקבעו החודש וכו' — TBD).
- **פרטי חשבון בנק**: אישור ניהול חשבון או צילום צ'ק.
- **תשלומים**: תשלום רק אחרי העלאת **חשבונית מס**; להוסיף דוגמת חשבונית; להציג ניכויים/עמלה.
- תיבת **בקשות**: שיוך יחידה↔ספק (דורש אישור), הצטרפות ספק↔יחידה, ושאלות/התחייבויות מטופלים.
- **רשימת המתנה**: כשאין תורים — מטופל מצטרף, נדרש הפנייה/חומר רפואי, הספק בודק ויכול לפתוח יום נוסף (מקביל בצד המטופל).

### יחידה רפואית
- היחידה **מדלגת** על הרשמה/אימות/הסכמות (הילסון מבצע מאחורי הקלעים ומנפיק כניסה) ומתחילה ישר ב**הקמה**.
- אותה הקמה: סניפים → מערכים → זמינות → פריטים → מחירים; **הסדרי ביטוח כן** (לפי סניף/מכון); **הסכם לא כאן**.
- היחידה יכולה **לחפש ספקים קיימים** (מספר רישיון, שם) או **להוסיף חדש** — תהליך ההוספה זהה לתהליך הספק העצמאי (כולל הסכם).

### נותני שירות שאינם רופאים (פיזיו וכו')
- אותו תהליך; **טיפול** מתנהג כפי שהוא.
- להוסיף **"תחום טיפול"** (למשל פיזיותרפיה → שיקומית / נוירולוגי) + **"אחר"** באישור אדמין.

## חלק ב' — צד מטופל (Patient)

### הרשמה ואימות
- כניסה בגוגל או מייל+סיסמה → פרטים אישיים.
- להוסיף שלב **אימות (OTP)** + לשמור אישור "נרשמת בהצלחה" וסימון סיום הרשמה ברור.
- אחרי הרשמה — **התראה** להשלמת פרופיל.
- לקלוט **טלפון בתחילת התהליך** (באימות) + שדה **"טלפון נוסף"** נפרד ("אפשר להשיג אותך במספר נוסף?", לא לצורכי כניסה) — קריטי ליצירת קשר על תורים.
- **להסיר** את אלמנט "מטופל רשום" שמוחק דאטה; **פרופיל = אזור אישי** — לאחד.

### פרטים אישיים
- שם מלא, מספר ת"ז, תאריך לידה, עיר + רחוב.
- **עיר/כתובת = חובה** (חלק מבתי החולים — הדסה, שערי צדק — דורשים כתנאי טיפול).
- **צילום ת"ז**; ללא אזרחות ישראלית — מסלול לא-אזרח + העלאת **דרכון** (ואז אפשר לא לבחור קופה).
- **שם האב** — חובה לקטינים מתחת ל-18; להפעיל אוטומטית לפי תאריך לידה.

### ביטוח וקופה
- בחירת **קופת חולים** עם אפשרות "ללא" (רלוונטי לדרכון/לא-אזרח); לאחר מכן בחירת **תוכנית** (מכבי בסיס/שלי/זהב/כסף וכו').
- ביטוח פרטי: להחליף "מספר פוליסה" ב**העלאת מסמך הפוליסה** (אופציונלי/בונוס, נדחה לשלב מאוחר) — המספר חסר ערך ללא המסמך.
- להוסיף **"שם סוכן"** אופציונלי, רצוי מרשימת סוכנים.
- מיקרו-קופי: "אם תוסיף את הפוליסה, נוכל לתת לך המלצות".

### הסכמות
- **הסכמה להספקת שירות** (נדרש בחוק).
- קישור ל**מדיניות פרטיות** (placeholder עד לסיום הניסוח).

### פרופיל / כרטיס מטופל
- להפוך **"אזור אישי" ל-דף הבית** שמציג **כרטיס מטופל**.
- אפשרות **להעלות פוליסות מתוך הפרופיל** תמיד (לא רק בהרשמה).
- כרטיס בראש המסך + נגיש מעיגול הפרופיל בצד; ברכת שם ("שלום נועה"), תמונה (אופציונלי), קופה/תוכנית וסיכום ביטוח פרטי (בסגנון כרטיס מאוחדת); אפשר להעלות מסמכי חברות ביטוח.
- **להסיר** פאנל "דברים לעשות" בהקמה — אין משימות הקמה למטופל.

### חיפוש — כניסה
- להציג בראש לפי מה מחפשים (הקשר).
- **שורת חיפוש חופשי** — לא לכפות מסלול פילטרים מובנה.
- בוררים ראשיים (בראש המסך), כל אחד פותח רשימה נגללת: **סוג פריט/שירות** (ייעוץ/טיפול/בדיקה/פעולה); **סוג נותן שירות** *או* **יחידה רפואית** (או/או); **תחום רפואי** (עם תת-תחום).
- בחירת סוג שירות פותחת את רשימת המסננים (כמו המסננים העליונים), לא קופצת ישר לתוצאות.

### חיפוש — מסננים
- להפריד פילטרים ראשיים (בר עליון) ממשניים (מגירה בצד, בסגנון Booking).
- **להעביר מיקום/אזור בארץ לבר הראשי** (כמעט תמיד רלוונטי).
- **גיל = קבוצת גיל** (למשל "16+"), לא גיל מדויק; מקור — טווח הגיל שבפריט.
- פילטר **מחיר** במסננים המשניים.

### תוצאות חיפוש / כרטיס פריט
- **פורמט כרטיס אחיד יחיד** לכל התוצאות (לא כרטיס "שירות" נפרד מכרטיס "נותן שירות").
- כל כרטיס = **פריט + נותן שירות/יחידה/סניף**; **הרופא/היחידה חסרים כיום בכרטיס** — חובה להוסיף.
- פריסת מובייל: מחיר שמאל-למעלה, שם בצד ימין; **מיקום גיאוגרפי בולט** (כרגע קבור בתחתית).
- להציג **קוד משרד הבריאות ראשון**, ואז שם הפריט המלא (לצורך חיפוש לפי קוד).
- **מחיר ראשי** ומתחתיו מחירים לפי קופה/הסדר; אם יש הסדר — להציגו, אחרת מחיר פרטי (שורת מחיר אחת לכרטיס).
- **להסיר** טקסט "משך" קשיח/מזויף אלא אם זה נתון אמיתי per-פריט.
- אותו פריט מופיע **פעם לכל יחידה/ספק** שמציע אותו (למשל MRI ראש ×5), כל אחד עם הסדר/מחיר משלו.

### תהליך הזמנה
- שני מסלולי הזמנה לפי סוג שירות:
  - **ייעוץ/טיפול**: בחירת slot ישירות (יום+שעה, חצאי שעות, משך per-פריט) → תשלום.
  - **דורש הפנייה** (כל מה שאינו ייעוץ/טיפול/מוצר): **אי אפשר** לבחור זמן קודם — העלאת **הפנייה** → אישור היחידה → **התראה** → ואז בחירת slot. לסדר את ה-wireframe בהתאם.
- לאפשר **כמה קודים בתור אחד** (למשל MRI ראש + חומר ניגוד) — תור אחד, מספר קודים.
- לאפשר צירוף **מסמך רפואי**; הפנייה מראש, שאר המסמכים הנדרשים לפני אישור התור.
- במסך אישור/תשלום להוסיף: **תנאי שירות**, מחיר מלא לתשלום, ו**מדיניות ביטול**.
- נוסח מדיניות ביטול: "ניתן לבטל את התור עד 48 שעות ממועד הזמנת התור ולקבל החזר של המקדמה בניכוי 5% או 100 ₪; לאחר מכן המקדמה לא תוחזר."
- אחרי תשלום: שמירת פרטי כרטיס אשראי, קבלה למקדמה, אישור תור, הוספה ל-Google Calendar, צפייה בתור.
- לכסות מצבי **משתמש לא רשום** (מה רואה משתמש לא מחובר) — נדחה, אך מסומן כנדרש.
